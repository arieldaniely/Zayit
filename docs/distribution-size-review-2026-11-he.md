# בירור גודל ההורדות והחלוקה לחלקים

נבדק ב־6 בנובמבר 2026 עבור #45. נתוני הספרייה נלקחו מנכסי ההפצה ומ־bundle-manifest.json
של [ההפצה המלאה v4](https://github.com/arieldaniely/SeforimLibrary/releases/tag/v4-20261024181224-semantic-41226932298-2).
הרשימה מציגה את מצב ההפצה שנבדק, ואינה תחזית לגודלן של הפצות עתידיות.

## מה צריך להוריד

קובצי ההתקנה של היישום הם חלופות לפי מערכת הפעלה וארכיטקטורה. משתמש Windows x64
אינו צריך להוריד גם ARM64, macOS ו־Linux. קובצי העדכון הקטנים ומפות הבלוקים מיועדים
לעדכון האוטומטי ואינם חלקי ספרייה שיש לאסוף ידנית.

לעומת זאת, part01 עד part05 של הספרייה המלאה הם חלקים של ארכיון אחד.
לייבוא ידני נדרשים כולם באותה תיקייה, ואז בוחרים part01 במתקין.
אין צורך לחלץ כל חלק בנפרד או להוריד גם את חבילת הבסיס וגם את החבילה המלאה.

## מה נמדד בפועל

הארכיון הדחוס הוא בגודל **8,105,621,413 בתים**, כ־8.11 GB עשרוניים.
ארבעת החלקים הראשונים הם בני 1,900,000,000 בתים כל אחד,
והאחרון בגודל 505,621,413 בתים.
המניפסט מציין **Zstandard ברמה 22**; סקריפט האריזה מבצע דחיסה מחדש של התוכן
ואימות חתימות, ולא רק חיבור ארכיונים ישנים.

SHA-256 של הארכיון:

`d530ccd181914d3f6803d3f87d1530b4f3de66e20617d3e9ca7a61e43a21fa46`

הרכיבים העיקריים לפני דחיסה, לפי אותו מניפסט:

| רכיב | בתים לפני דחיסה |
| --- | ---: |
| מסד הספרים seforim.db | 8,593,604,608 |
| אינדקס הטקסט seforim.db.lucene | 5,151,172,132 |
| האינדקס הסמנטי החדש | 2,366,433,609 |
| המודל והטוקנייזר | 44,681,236 |
| קובצי PDF | 473,511,335 |
| המילון lexical.db | 81,035,264 |

גדלים לא דחוסים אינם מעידים במדויק על חלקו של כל רכיב בהורדה.
אינדקסי חיפוש, וקטורים ו־PDF אינם נדחסים כמו טקסט חוזר.

## האם אפשר להסתפק בשלושה חלקים קטנים יותר

GitHub מגביל כל נכס בהפצה לפחות מ־2 GiB.
שלושה נכסים כאלה יכולים להכיל פחות מכ־6.44 GB, ולכן אינם מספיקים לארכיון הנוכחי.
בגבול החלקים הנוכחי, 1.9 GB, חמשת החלקים הם תוצאה צפויה של הגודל שנמדד.
הקטנת מספר החלקים לבדה אינה מקטינה את סך הבתים.
ראו [מגבלות נכסי הפצה ב־GitHub](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases).

יש ממצא ששווה לבדוק באופטימיזציה עתידית: גם אינדקס הטקסט הישן מכיל קובצי
Lucene HNSW עם סיומות vec ו־vex, בנוסף לאינדקס הסמנטי החדש.
שני הקבצים הגדולים האלה באינדקס הישן מסתכמים ב־1,678,522,701 בתים לא דחוסים.
זו ראיה לנתוני וקטורים ישנים, אך אינה הוכחה שאפשר למחוק אותם בבטחה,
ואינה מדידה של החיסכון לאחר דחיסה. יש להסיר שדות וקטור דרך כלי Lucene,
לשמור את שדות הטקסט, ולבדוק חיפוש לפני יצירת הפצה חלופית.
מחיקת קובצי האינדקס ישירות עלולה להשחית אותו.

הקוד כבר כולל תהליך דחיסה ברמה 22. לכן הבטחה לחבילה קטנה בהרבה מחייבת מדידה
לאחר שינוי בהרכב האינדקסים או ברכיבים הכלולים, ולא העלאה נוספת של רמת הדחיסה.
לא שונתה ולא הוחלפה ההפצה הקיימת במסגרת בירור זה.
