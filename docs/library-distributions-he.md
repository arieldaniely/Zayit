# חבילות התקנה של זיתא

הורדת מסד הספרים היא מתוך `arieldaniely/SeforimLibrary`. ההתקנה המקוונת בוחרת את
`seforim_bundle.tar.zst` (או את כל חלקיו), שהיא החבילה המלאה. בייבוא מקומי מותקנים
בדיוק הרכיבים שנמצאים בחבילה שנבחרה. רכיבים חסרים מוצעים בנפרד וניתן לדלג עליהם.

## הגבלות הפצה של המודל והווקטורים

חל איסור מוחלט להפיץ מחדש את מודל הבינה המלאכותית (AI) ואת הווקטורים המופצים עם התוכנה או בחבילות ההשלמה שלה, כולם או חלקם, בכל דרך, לרבות כחלק מחבילה אחרת או כשהם משולבים במוצר אחר, ללא קבלת אישור מראש ובכתב מ־arieldaniely@gmail.com. רישיון קוד התוכנה אינו מעניק רשות להפיץ מחדש רכיבים אלה.



תחילה מריצים `incremental-inject-release.yml` במאגר `arieldaniely/SeforimLibrary`.
הריצה מורידה גרסת מקור מוגדרת של זית, מאמתת את חלקי ההורדה, מזריקה רק את הספרים
המאושרים החסרים ובודקת שהמידע הקיים על המחברים, הספרים והרישיונות נשמר.
רק לאחר סיום מוצלח משתמשים בתג הטיוטה שנוצר כ־`DB_RELEASE_TAG` במחברת.

## קאגל: אינדקס בלבד

המחברת היא `notebooks/build_semantic_index_kaggle_t4x2.ipynb`.
יש לבחור T4 x2 ולהפעיל Internet. הסוד `HF_TOKEN` צריך גישה למודל המאושר.
`GH_TOKEN` נדרש לקריאת מסד בטיוטה; הרשאת כתיבה למאגר Zayit נדרשת רק אם מפעילים
`UPLOAD_TRANSFER`. אין לשים טוקנים בתאי המחברת.

שני עובדים מייצרים וקטורים במקביל. נקודות שמירה כוללות את טביעת המסד, המודל וחלוקת
העבודה; חידוש חותך רק את הקצה שלא הושלם וממשיך מהמזהה האחרון שנשמר. עומס זיכרון
GPU מפצל אוטומטית את האצווה. שגיאה באחד העובדים עוצרת גם את השני ומוצגת מיד.
נקודות השמירה נשמרות ב־`/kaggle/temp`, ולכן זמינות לחידוש באותה סביבת הרצה בלבד.
מחיקה או החלפה של סביבת קאגל מוחקת אותן.

הפלט ב־`/kaggle/working/semantic-output` כולל רק:

- `semantic-transfer.json`, עם זהות המסד, המודל ובדיקות SHA-256.
- `semantic-index.tar.zst.part01` והחלקים העוקבים של אותו זרם דחוס.

החלקים בגודל מרבי 1.9GiB, כלומר 2,040,109,465 בתים, מתחת למגבלת GitHub של 2GiB.
ברירת המחדל היא Zstandard ברמה 3; אפשר לבחור 1–6. מסד הנתונים, המודל, PDF,
וקטורי הביניים ופרטי הגישה אינם נכללים בפלט. אינדקס Lucene אחד נבנה משני העובדים;
האיחוד היקר למקטע אחד נדחה ל־Actions. המחברת מושכת קוד מהמאגר ואינה דורסת אותו
באמצעות עותקים מוטמעים ישנים. מזהה הקומיט מודפס כדי שאפשר יהיה לשחזר את הריצה.

## Actions: איחוד ודחיסה מרבית

אפשר להעלות את הפלט אוטומטית לטיוטה באמצעות `UPLOAD_TRANSFER=True`, או להעלות
ידנית את המניפסט ואת כל החלקים לאותה טיוטת Release במאגר Zayit.
לאחר מכן מריצים `finalize-semantic-index.yml` עם תג המסד ותג טיוטת ההעברה.

הסודות הנדרשים במאגר Zayit:

- `SEFORIM_LIBRARY_TOKEN`: קריאת טיוטת המסד ויצירת טיוטות במאגר הספרייה.
- `HF_TOKEN`: גישה למודל המאושר. ההורדה נבדקת מול טביעות קבועות בקוד.

הריצה מאמתת את כל הקבצים ואת ההתאמה המדויקת למסד ולמודל, מאחדת את מקטעי Lucene
בלי להריץ מודל או לחשב וקטורים מחדש, ואז אורזת את התוכן מחדש ברמה 22. זו דחיסה
מחודשת של התוכן, ולא שרשור של ארכיונים בדחיסות שונות. אין צורך בקובץ ביניים גדול
של ארכיון מאוחד: הכתיבה והחלוקה לחלקים מתבצעות בזרימה.

נוצרות שתי טיוטות עם תגים חדשים וקישורים בסיכום הריצה: מסד עם הקטלוג, האינדקסים,
המידע על מחברים וספרים והאינדקס הסמנטי; ותוסף סמנטי נפרד להתקנה קיימת התואמת
לאותו מסד. PDF שכבר נמצא בחבילת הבסיס נשמר; הריצה אינה מורידה ספרי PDF נוספים.
הארכיונים הסופיים מחולקים גם הם לחלקים של 1.9GiB לצורך העלאה. לכל ארכיון
מניפסט עם גודל וטביעות החלקים. הטיוטות אינן מתפרסמות אוטומטית לציבור.

## אימות שבוצע ומגבלות

נבדקו פיצול ושחזור ארכיונים, דחיסה ברמה 22, דחיית חלק פגום, חידוש נקודת שמירה
ללא כפילויות ואיחוד Lucene אמיתי תוך שמירת הווקטורים והמזהים. כלי הבנייה של Kotlin
קומפלו בהצלחה. ריצת GPU מלאה על כל המאגר ומשך הדחיסה הסופית טרם נמדדו.
