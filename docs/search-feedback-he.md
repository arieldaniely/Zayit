# איסוף משוב לחיפוש

איסוף הנתונים פעיל כברירת מחדל וניתן לכיבוי ב״הגדרות ← כללי ← שיתוף נתונים לשיפור החיפוש״.
כניסה לתוצאה, כולל פתיחה במהדורת PDF, שולחת אירוע `entry` בכל מצבי החיפוש.
כפתורי לייק ודיסלייק מופיעים בריחוף מעל תוצאה בחיפוש חכם בלבד. כיבוי האיסוף מסתיר אותם.
בחיפוש חכם שעבר לחיפוש גמיש עקב אי־זמינות המודל, מצב החיפוש בפועל נשלח כ־`flexible`.

## ממשק השרת

כתובת הבסיס: `https://arielll123-meivin-api-data.hf.space/gradio_api`.

1. `POST /call/v2/save_feedback` עם גוף `{"data": { ... }}` ו־`Content-Type: application/json`.
2. חילוץ `event_id` מהתשובה.
3. `GET /call/save_feedback/{event_id}` וקריאת זרם האירועים עד `event: complete` עם `success: true` בתוצאה.
   אירוע `error`, שגיאת HTTP או העדר אישור השלמה נחשבים לכישלון שליחה.

## שדות הנתונים (גרסת סכימה 1)

| שדה | משמעות |
| --- | --- |
| `schemaVersion` | גרסת מבנה הנתונים |
| `id`, `eventId`, `occurredAt` | שני שדות עם אותו מזהה אירוע אקראי, וזמן הלחיצה ב־UTC. `id` משמש את השרת לשם הקובץ ומונע יצירת קובץ חדש בניסיון חוזר |
| `software`, `softwareVersion` | זיתא וגרסת התוכנה |
| `databaseVersion` | גרסת המאגר מתוך `release_info.txt`, אם זמינה |
| `modelVersion` | שם מודל ONNX ו־SHA-256 בחיפוש חכם; אחרת `null` |
| `feedbackType` | `like`, `dislike` או `entry` |
| `search.searchId`, `search.query` | מזהה חיפוש אקראי והשאילתה שבוצעה |
| `search.requestedMode`, `effectiveSearchMode` | מצב מבוקש (`EXACT/FLEXIBLE/SMART`) ומצב שבוצע בפועל (`exact/flexible/smart`) |
| `search.near` | פרמטר הקרבה של מנוע החיפוש |
| `search.bookFilter`, `search.categoryFilter` | סינון הספר או הקטגוריה שנמסר למנוע |
| `search.bookIds`, `search.lineIds` | מזהי הספרים או השורות שהגבילו את ביצוע החיפוש; `null` פירושו ללא הגבלה מסוג זה |
| `search.baseBookOnly` | האם החיפוש הוגבל לספרי יסוד |
| `bookId`, `bookTitle`, `lineId`, `lineIndex` | זיהוי מקור התוצאה; אינדקס השורה מתחיל ב־0 |
| `paragraph`, `paragraphHtml` | התוכן המלא של השורה במאגר, כטקסט וכ־HTML; אינו נלקח מהתקציר |
| `snippetHtml`, `matchedParts` | התקציר בעת הלחיצה והטקסטים שהודגשו בו; רשימה ריקה אם טרם אותרו מילים |
| `resultPosition`, `retrievalPosition` | מקום ברשימה המוצגת לאחר סינון ובתוצאות הטעונות לפני הסינון; שניהם מתחילים ב־1 |
| `relevanceScore` | ציון רלוונטיות; אינו מיקום התוצאה |
| `loadedResultCount`, `totalResultCount` | מספר התוצאות המוצגות שכבר נטענו ומספר התוצאות הידוע למנוע |
| `selectedBookIds`, `selectedCategoryIds`, `selectedTocIds` | הבחירות הפעילות בעץ הסינון בעת הלחיצה |
| `viewBookId`, `viewCategoryId`, `viewTocId` | תחום התצוגה הפעיל בעת הלחיצה |
| `destination` | `text` או `pdf` בכניסה לתוצאה; `null` בדירוג |

שאילתה ופרמטרי הביצוע נשמרים מתוך סשן החיפוש, ולכן עריכת שדה החיפוש לאחר הצגת התוצאות
אינה משנה אותם. כאשר התוצאות שוחזרו מזיכרון ללא סשן פעיל, נעשה שימוש בהקשר המשוחזר הזמין.
ערכי `null` מציינים מידע שאינו זמין; מיקום שאינו זמין אינו מומצא.

## התנהגות השליחה והבדיקות

האירועים נכתבים ברקע לקבצי JSON בתיקיית `search-feedback` ליד מסד נתוני הגדרות המשתמש,
באופן אטומי. התור אינו תלוי בחיי טאב החיפוש ונשמר גם לאחר סגירת התוכנה.
ניסיון שליחה מתבצע בעליית התוכנה, לאחר הוספת אירוע ובכל חמש דקות.
אחרי כשל רשת, האירועים נשארים בדיסק והניסיון הבא מתבצע כעבור חמש דקות.
אירוע נמחק רק לאחר אישור השלמה מהשרת, או לאחר חודשיים קלנדריים מזמן האירוע.
מזהה המשימה של Gradio נשמר בדיסק אחרי POST, כך שניתן להמשיך את אישור אותה משימה
לאחר ניתוק או הפעלה מחדש. אם המשימה פגה או נכשלה, האירוע נשלח מחדש בניסיון הבא עם אותו `eventId`.
השדה `id` נשלח עם אותו ערך כמו `eventId`: במימוש השרת הנוכחי הוא משמש לשם הקובץ במאגר,
כך ששליחה חוזרת של אותו אירוע כותבת לאותו קובץ.
התנהגות זו תואמת ל[קוד השרת](https://huggingface.co/spaces/ArieLLL123/Meivin-API-Data/blob/main/app.py).
כיבוי האיסוף מונע יצירת אירועים ושליחת אירועים שממתינים בדיסק; בקשה שכבר התחילה עשויה להסתיים.
נתונים שנשמרו לפני הכיבוי נשארים עד חודשיים וניתן לשלוח אותם לאחר הפעלה מחודשת של האיסוף.
לוגי כשל אינם כוללים את השאילתה או את תוכן הפסקה.

לא נאספים שם משתמש, דוא״ל, מזהה התקנה או נתיב מקומי של המאגר.
לשיפור ניתוח המשוב בעתיד ניתן לשקול סיבת דיסלייק, זמן קריאה ונתוני חשיפה לתוצאות.
אלה אינם נאספים במימוש הנוכחי.

הבדיקות מכסות חילוץ מילים מודגשות, צילום פרמטרי חיפוש, fallback,
בקשת POST ומעטפת JSON בשרת HTTP מקומי, קריאת אישור SSE וטיפול בשגיאות.
בדיקות היחידה אינן שולחות רשומות בדיקה למאגר הייצור.
