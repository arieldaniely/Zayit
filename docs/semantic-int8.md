# וקטורים סמנטיים ב־int8

מחברת `notebooks/build_semantic_index_kaggle_t4x2.ipynb` מפעילה את
`scripts/kaggle_embed_vectors.py` ואת `scripts/kaggle_semantic_bundle.py`.
הווקטורים מכומתים ב־GPU pipeline לאחר הפקת embedding ב־float32, ונשמרים ב־int8
גם בקובצי הביניים וגם בשדות `KnnByteVectorField` של Lucene. מודל ה־ONNX אינו משתנה.

הכימות `int8-maxabs-v1` מחלק כל רכיב בערך המוחלט המרבי בווקטור, מכפיל ב־127,
ומעגל באמצעות `floor(x + 0.5)`. הערכים בטווח ‎−127…127.
חיפוש cosine אינו דורש את מקדם הסקלה, ולכן אין צורך לשמור אותו.
אותו כימות מוחל בתוכנה על וקטור השאילתה. הכימות כרוך באובדן דיוק; יש להעריך
איכות תוצאות על שאילתות אמיתיות לפני הפצת אינדקס מלא.

וקטור בן 256 רכיבים תופס 256 בתים במקום 1,024. רשומת ביניים עם מזהי שורה וספר
ודגל ספר בסיס תופסת 276 בתים במקום 1,044. גרף HNSW, מזהים ומטא־נתונים נשארים
חלק מהאינדקס, ולכן גודל החבילה הכולל אינו קטן בהכרח פי ארבעה.

קובץ הביניים מתחיל ב־8 הבתים `ZYVECI8\n`, ואחריהם ממד הווקטור כ־uint32
ב־little endian. כל רשומה מכילה `line_id` ו־`book_id` כ־int64, את `is_base_book`
כ־int32, ואז 256 בתים חתומים. קובצי float32 ישנים ללא כותרת עדיין נתמכים בייבוא,
אך גם הם נכתבים לאינדקס החדש כ־int8.

`semantic.properties` כולל `vectorEncoding=int8-maxabs-v1`. התוכנה תומכת גם
באינדקסים ישנים ללא השדה הזה, ובודקת שסוג הווקטור ב־Lucene תואם למניפסט.
סקריפט Kaggle משתמש בתוצרי הרצה קודמת רק כשהם תואמים לפורמט int8; חלקי אינדקס
ישנים נבנים מחדש. כדי לקבל את החיסכון יש להריץ מחדש את המחברת ולהחליף את החבילה.

המחברת מושכת כברירת מחדל את `master`. לפני הרצה ב־Kaggle יש לפרסם את שינויי
התוכנה והסקריפטים ואת עדכון מצביע תת־המאגר `SeforimLibrary`; אפשר לבחור ענף אחר
באמצעות `ZAYIT_REF`. מחברת מקומית מעודכנת לבדה אינה מעדכנת את הקוד ש־Kaggle מוריד.

בדיקות ממוקדות: `./gradlew -p SeforimLibrary :search:jvmTest --tests '*Int8VectorsTest' --tests '*VectorSearcherTest' --tests '*BuildSemanticIndexFromVectorsTest'`.
